## graphify <!-- res_7d540630d9c3da46710b4fca -->

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

When the user types `/graphify`, use the installed graphify skill or instructions before doing anything else.

Rules:
- For tasks that identify the relevant files or symbols, inspect those sources directly. For unresolved architecture, file relationships, or project-content discovery, use Graphify when an allowed read confirms graphify-out/graph.json exists and the command is available and permitted: `graphify query "<question>"` for discovery, `graphify path "<A>" "<B>"` for relationships, and `graphify explain "<concept>"` for focused concepts. Target a specific symbol, source path, or relationship and bound query output with `--budget`. If results are noisy, heavily truncated, or unhelpful, narrow once or return to targeted source inspection. Verify graph findings in source.
- If Graphify is unavailable or denied, continue permitted source inspection without retrying the denied command or making Graphify approval a prerequisite for implementation or testing. Respect explicit requests not to use Graphify. Dirty graphify-out/ files are expected after hooks or incremental updates; dirtiness alone does not prevent a useful lookup. Investigate stale or incorrect graph output against source.
- Use graphify-out/wiki/index.md, when present, for broad navigation; search for relevant entries and read bounded excerpts. Skip it for already localized tasks. Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- Run `graphify update .` when graph maintenance is requested or explicitly required by the project, or a concrete freshness need requires it for the current task. Code edits alone do not require a refresh. Defer broad regeneration for localized edits unless needed; use a scoped refresh only if documented and verified to be supported. Batch maintenance after final edits, formatting, and validation, unless a refresh is needed for intervening work. Keep code-only extraction AST-only, with no LLM API cost.
- Updates can still take time, regenerate artifacts, and change community labels. Before updating, check existing working-tree changes; afterward, review the generated diff and preserve unrelated changes. Report material artifact changes, curated-label changes or relabeling warnings, and any required refresh that was deferred.
